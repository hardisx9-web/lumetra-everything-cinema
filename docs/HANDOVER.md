# Lumetra handover — 8 October 2026

## Release scope
The release uses the supplied original opening MP4, logo and stage artwork. Two generated photographic auditorium plates frame the original video. The frontend provides the cinematic homepage, intro/replay/sound/skip, mobile navigation, real catalogue search and filters, pagination, film dossiers, connected people queries, history/world introductions, editorial reading and moderated correction submission.

The serving database is Cloudflare D1, populated from the preserved PostgreSQL catalogue export: 20,512 works, 23,711 historical playback records, 3,883 eligible source records across 2,975 works at export. Eligibility expires after seven days; current counts can be lower. There are no approved embedded sources. Loading a provider page is not treated as proof of free viewing. The original PostgreSQL dump is not published.

## Architecture and costs
The existing authorized Sites deployment provides HTTPS, Worker API, D1 and static media. No paid subscription or external infrastructure was activated. This avoids transferring the whole catalogue into browser JavaScript. Hosting quotas are account-dependent, not a promise of unlimited free operation. A live managed PostgreSQL connection, paid storage and custom domain are not configured.

## Build and deployment
Use the Sites source workflow and build helper documented by the Sites plugin. The project uses the existing project identity in .openai/hosting.json. Apply additive Drizzle migrations through that workflow. Never publish raw uploads, dumps or .env files. The first empty-database launch resumes the immutable server-side publication import. Search and detail APIs use bound SQL parameters, server pagination and FTS. Source verification timestamps remain historical; do not refresh timestamps without rechecking evidence.

## Data and editorial maintenance
Original ingestion code is retained in preserved-ingestion/. Its package scripts and source registry remain the starting point for future imports. Run its tests before modifying provider adapters. Keep PostgreSQL as the archival source of truth; review/deduplicate enrichment before exporting a new serving snapshot. The export must retain native IDs, source provenance and timestamps, strip private fields, and pass scripts/test-hosted.mjs. Back up the original dump separately and export the serving database through the hosting owner's database facilities before migrations.

New correction submissions enter correction with PENDING status. There is no public read endpoint for submissions. Staff must review in the database; a staff moderation interface and scheduled ingestion are not delivered. editorial_revision and artwork_record provide additive schema for review and licensing. Do not automatically publish generated prose or unverified artwork. New essays in catalogue-editorial/research.js label interpretation and provide sources; comprehensive human editorial review remains outstanding.

## Material gaps
This is a substantial functioning release, not completion of every master-brief requirement. Live PostgreSQL hosting, full constraint-validated restoration, scheduled continuous ingestion, broad artwork licensing, extensive new country/technology/people dossiers, staff editorial UI, per-record server SEO, and full device/production browser QA remain unfinished. The isolated PGlite restore verified main catalogue counts but imported only 23,681 of 33,958 ingestion candidates; related constraint failures reflect an incomplete restoration, not proven corrupt source data. docs/restored-counts.json describes that partial restore. Temporary scratch audit state was lost during environment maintenance; recover the original uploaded dump for a fresh native PostgreSQL restore. All 14,470 imported media records were unverified for licensing and were not mass-published.
